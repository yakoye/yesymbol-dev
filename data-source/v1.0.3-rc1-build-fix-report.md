# YeSymbol v1.0.3-rc1 编译修复报告

## 问题

Windows SDK 10.0.26100 的 `dwrite.h` 在 MSVC `/TC` C 模式下出现 `C2059`、`static_cast` 未声明等错误，错误全部来自 `src/emoji_renderer.c` 引入 DirectWrite 头文件的编译单元。数据生成与目录审计已经成功，失败发生在 C/C++ 编译阶段。

## 根因

DirectWrite SDK 头文件包含 C++ 专用构造。`COBJMACROS` 只能提供 C 风格 COM 调用宏，不能让 C 编译器识别头文件中的 C++ 语法。

## 修复

1. CMake 启用 C、C++ 和 RC 三种语言。
2. 仅将 `src/emoji_renderer.c` 设置为 C++ 编译器模式。
3. 在该文件定义 `CINTERFACE` 和 `COBJMACROS`，继续使用 C 风格 COM vtable 宏。
4. `emoji_renderer.h` 使用 `extern "C"`，确保其余 C11 模块链接名称稳定。
5. C++ 桥接关闭 RTTI，不使用 STL；静态 CRT、单 EXE 和 GDI 回退不变。
6. 版本按候选版规则升级为 `v1.0.3-rc1`。

## Windows 验证命令

```powershell
.\build.bat all
.\build.bat run
```

预期 `emoji_renderer.c` 由 `cl.exe` 的 C++ 模式编译，不再出现 `dwrite.h` 的 C 语法错误。
