# YeSymbol v1.0.3-rc2 目录清理报告

## 问题结论

- 上传的 `catalog(6).txt` 语法可以被转换器解析，16,679 条符号定义没有丢失。
- 构建中断的直接原因是 `补充符号 → 萨顿手语书写` 仍属于审计规则认定的“可以归入正式分类”的分组。
- 文件中存在 37 组同名二级标题，共有 42 个多余的重复标题实例。
- 同一一级分类内存在 1 个重复符号引用：`特殊符号` 中的 `☯`。

## 已执行处理

1. 将 `萨顿手语书写` 从 `补充符号` 移到 `象形文字`。
2. 同一一级分类中的同名 `## 二级标题` 合并到第一次出现的位置。
3. 后续同名分组的符号行按原始顺序追加，符号内容不丢失。
4. 删除同一分类中重复的 `☯` 引用，保留在更明确的 `宗教、文化与公共标识` 分组。
5. 转换器增加自动防护：以后即使 TXT 中再次出现同名二级标题或已知可移动补充分组，生成 JSON 时也会自动合并、归类并报告数量。

## 使用

将本版 `data-source/catalog.txt` 替换到项目中后执行：

```powershell
.\build.bat data
```

正常输出会包含：

```text
merged 0 duplicate group headings
reclassified 0 supplement groups
catalog audit passed
```

因为清理后的 TXT 已经没有重复；转换器中的自动处理逻辑用于防止以后再次出现同类问题。
