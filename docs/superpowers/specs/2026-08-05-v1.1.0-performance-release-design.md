# YeSymbol v1.1.0 性能与发布设计

## 目标

将现有 Emoji 图片化改造整理为可正式发布的 v1.1.0，同时解决常用符号布局不一致、连续自动插入不跟手、全量 Emoji 预热占用资源过高等问题。最终交付一个经过自动化与实机验证的 Windows x64 单文件程序，并提交、推送代码，创建 GitHub `v1.1.0` 正式 Release。

## 当前基线与已确认根因

当前 Release EXE 为 6,328,832 字节。程序运行稳定后测得工作集约 80.05 MB、私有内存约 57.18 MB、2,178 个 GDI 对象、12 个线程。空闲 CPU 已归零，但进程仍长期保留已解码位图和相关资源。

资源占用的主要原因是程序启动后使用最多四个工作线程预热整个 Emoji 目录。约 3,826 个逻辑 Emoji 会逐步解码为 GDI 位图，获得后续绘制速度的同时，也让未被用户浏览的图片长期占用内存和 GDI 对象。

连续点击的关键路径仍包含两个同步操作：抢占剪贴板，以及在 YeSymbol 和此前目标窗口之间反复恢复前台窗口与焦点。剪贴板重试虽然已减少固定休眠，但仍运行在 UI 线程；自动插入时的焦点往返则是快速连点不够丝滑的主要结构性原因。

常用符号第 12 列变宽是因为该页面使用“平均铺满可用宽度”的专用布局，最后一列还会吸收除法余数；其他符号网格使用固定宽度单元格，所以两者观感不一致。

“其他符号”后的方框来自当前界面字体无法显示 `⯈`、`⯆`，不是目录中的空字符。

## 方案选择

采用“按需 Emoji 缓存 + 不激活符号点击 + 非阻塞剪贴板 + 生成式常用分类”的平衡方案。

不保留全量预热，因为它无法满足低内存、低 GDI 对象和低后台任务占用目标。也不在 v1.1.0 中重写整个资源容器；现有压缩 PNG 已能把 3,826 个逻辑映射控制在约 3.4 MB，重新设计二进制资源包会显著扩大回归面，却不会直接改善用户点击体验。

## 界面与尺寸

- `YS_EMOJI_IMAGE_SIDE` 从 24 调整为 36，主网格和最近使用均绘制居中的 36×36px Emoji 图片。
- 主符号单元格继续为 46×44px；图片在单元格内按中心对齐，允许图片高度接近单元格，但不改变命中区域。
- 常用符号改用与普通分类相同的固定宽度布局，每行最多 12 项，不再平均拉伸，也不再让第 12 列吸收剩余宽度。
- 折叠标题使用纯 ASCII：折叠为 `其他符号 >`，展开为 `其他符号 v`。这样不依赖特殊字体，同时明确表达状态。
- 现有固定窗口尺寸、分类宽度、最近使用槽位和高 DPI 行为保持不变。

## 常用符号目录与持久化

### 人工源格式

删除 `@default-common` 顶层指令，改用普通一级分类：

```text
# 常用符号
@role common

✓,✔,☑,✕,✖,...
```

`@role common` 是结构标记，避免生成器依赖可编辑的中文标题。它只允许出现在一个一级分类中；该分类最多 256 个去重序列。用户通过编辑普通符号行、执行 `build.bat data`，即可重新生成默认常用内容。

生成器继续输出运行时需要的默认常用索引，但这些索引从 `role=common` 分类推导，不再从独立元数据字段读取。动态常用页面在侧边栏只显示一次；静态 common 分类不会再作为第二个普通分类入口出现。它的符号仍进入“全部符号”、搜索索引和名称数据库。

### CommonV3

持久化升级为 `CommonV3`。每个常用项记录：

- `text`：实际复制和插入的 Unicode 序列；
- `use_count`：累计使用次数；
- `serial`：稳定顺序标识；
- `origin`：编译期默认项或用户/自动追加项。

另存一个被用户明确删除的默认项集合，作为 suppression tombstone。启动时执行以下合并：

1. 删除已经不在新版 `# 常用符号` 中的旧默认项；
2. 保留仍存在的默认项、使用次数和用户调整后的相对顺序；
3. 新增的编译期默认项按目录顺序加入默认区域；
4. 保留所有手工加入或达到阈值后自动追加的项目及其相对顺序；
5. 用户曾明确删除且仍在默认目录中的项目不自动恢复；
6. 用户以后再次手工加入该项目时清除 suppression 标记。

从 `CommonV2` 首次迁移时，当前列表中匹配编译期默认集合的项目标记为默认，其余项目标记为用户/自动追加。当前 v1.1.0 的 `# 常用符号` 初始内容必须与旧 `@default-common` 完全一致，因此可把旧列表中缺少的默认项识别为用户已删除项，避免升级后意外恢复。

存储异常、版本不匹配或注册表内容损坏时，程序使用编译期默认项启动，不阻止主窗口打开；下次保存写入新的 `CommonV3`，但不主动删除旧 `CommonV2`，以便回退旧版程序。

## 连续复制与自动插入

### 不激活符号点击

主符号网格和最近使用网格处理 `WM_MOUSEACTIVATE` 时返回不激活结果。用户从编辑器点击符号时，目标编辑器仍保持前台和输入焦点，YeSymbol 不再为每个符号执行一次完整的前台窗口往返。

搜索框、分类列表、自定义输入框、设置按钮和右键菜单仍允许正常激活 YeSymbol。主窗口在这些交互发生前继续记录此前的外部目标窗口，保证之后的符号点击仍能找到插入目标。

### 输入顺序

勾选自动插入后，点击处理先向仍处于焦点的目标控件发送完整的 `KEYEVENTF_UNICODE` 输入批次。每次点击形成一个不可拆分的批次；Windows 消息队列保持批次先后顺序。若目标已经失效，程序只完成复制并在状态栏提示，不向其他未知窗口发送输入。

需要兼容窗口重新激活的场景时，保留现有目标恢复逻辑作为降级路径，但正常的不激活点击不会进入该路径。

### 非阻塞剪贴板

UI 线程只尝试立即打开剪贴板一次，不执行 `Sleep`、自旋或同步重试。成功时立即写入；失败时把最新符号保存为待复制内容，通过窗口消息或短定时器重试。连续点击期间待复制内容可以合并为最新值，因为系统剪贴板最终只可能保存一个当前值；自动插入和最近使用记录仍逐个处理，不会被合并。

退出前如仍有待复制内容，执行一次有上限的最终尝试，不无限等待。注册表保存继续使用已有 350ms 合并机制，不进入输入关键路径。

## Emoji 渲染与资源上限

### 压缩资源

保留构建期生成的压缩 PNG blob 和文本索引。正常运行不读取 `catalog.txt`、JSON 或外部图片，也不增加网络依赖。Emoji 下载缓存是本机构建缓存，不作为数千个零散文件提交；生成后的 C 数据继续提交，使普通 `build.bat build` 可以离线编译。

`build.bat run` 只负责停止旧进程、清理、编译和运行，不再隐式重复下载/生成数据。需要更新目录或图片时显式执行 `build.bat data`；`build.bat all` 仍执行完整数据生成与干净构建。

### 有界缓存

移除启动时遍历全目录的四线程预热。新的解码策略为：

- UI 首次需要某张图片时提交按需解码；未完成前使用现有字体回退，不阻塞消息循环；
- 当前可见区域优先，随后最多预取下一屏；
- 使用一个后台工作线程，重复请求按文本去重；
- 解码完成后向 UI 线程投递刷新消息，UI 线程负责失效对应网格；
- 图片位图保存实际 36×36px 像素，不再为每张图片保存完整 46×44px 空白画布；
- 使用容量 384 的 LRU 位图缓存，超过容量只淘汰最久未使用且当前未绘制的项；
- 字体回退布局缓存保持独立，并设置明确上限；
- 退出时设置取消标志、唤醒并等待唯一工作线程，再释放缓存和 COM/WIC 资源。

384 张 36×36×4 位图的裸像素约为 1.9 MB，能够覆盖多个可见屏幕，同时把 GDI 对象数量限制在可控范围。

## 性能与正确性验收

发布前记录同一台机器、同一 Release 构建的改造前后数据。至少包括：

- 冷启动到主窗口可交互时间；
- 启动后 2 秒及空闲 60 秒的工作集、私有内存、线程数、句柄数和 GDI 对象数；
- 打开每个 Emoji 大分类后的首次可见时间和滚动响应；
- 连续输入 `❶❷❸❹❺❻❼❽❾❿⓫⓬⓭⓮⓯⓰⓱⓲⓳⓴` 的总耗时、完整性和顺序；
- 自动插入关闭时连续复制，最终剪贴板内容必须等于最后点击的符号；
- EXE 文件大小和 SHA-256。

接受标准：

- 快速连点测试不丢字符、不乱序；
- 点击处理路径不存在休眠或同步重试循环；
- 空闲 CPU 回到 0%，后台最多一个 Emoji 解码工作线程；
- Emoji 位图缓存最多 384 项，GDI 对象不再随浏览完整目录持续增长；
- 稳定私有内存和工作集显著低于当前 57.18 MB / 80.05 MB 基线；
- EXE 不因本次改造出现无理由的大幅增长；
- `build.bat data`、静态检查、Emoji 数据检查、Release 编译和交互回归全部通过。

快速输入测试使用一个测试专用 Win32 文本接收窗口，真实保持目标焦点并驱动 YeSymbol 网格点击，最后读取接收文本。该工具只属于 `tests/`，不链接进正式 EXE。

## 测试策略

遵循测试先行：先增加会失败的检查，再修改实现。

1. 数据测试验证源文件不含 `@default-common`、恰有一个 `role=common` 分类、生成默认索引与该分类逐项一致。
2. CommonV3 单元测试覆盖 V2 迁移、默认项新增/删除、自动追加保留、suppression、去重、容量上限和损坏数据回退。
3. 布局测试验证常用符号 12 列使用固定 46px 步长，最后一列不拉伸。
4. Emoji 测试验证 36px、异步请求去重、384 项上限、LRU 淘汰和退出取消。
5. 快速输入集成测试验证 20 个编号符号无丢失、无乱序，并检查最终剪贴板。
6. 现有 `tests/static_check.py` 与 `tests/emoji_images_check.py` 全量回归。
7. 执行 `build.bat data` 和干净 Release 编译，人工检查主网格、最近使用、搜索、常用、其他符号折叠、托盘和关于窗口。

## 发布流程

1. 确认工作树只包含本次及此前已验收的 Emoji 图片化改动。
2. 运行完整数据生成、测试、干净构建和交互验收。
3. 记录 EXE 大小、性能基线对比与 SHA-256。
4. 生成 `yesymbol-v1.1.0-windows-x64.zip`，包含 `yesymbol.exe`、LICENSE 和简明使用说明。
5. 提交源码和必要生成文件，不提交本地缓存与构建目录。
6. 推送当前分支到 GitHub。
7. 创建带注释标签 `v1.1.0` 并推送。
8. 创建非草稿、非预发布的 GitHub Release，上传 EXE、Windows x64 ZIP 和 SHA-256 文件，发布说明包含主要变化、系统要求、使用方式、数据位置、第三方图片来源和已知限制。

如果 GitHub 推送、标签或 Release 创建因认证、分支保护或远端状态失败，保留已经验证的本地提交和发布文件，报告准确错误，不覆盖远端历史，也不使用强制推送。
