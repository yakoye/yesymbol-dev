# YeSymbol v1.1.0 性能与发布 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 36px Emoji、生成式常用分类、无丢失快速插入、有界图片缓存、文档整理和 GitHub v1.1.0 正式发布。

**Architecture:** `catalog.txt` 通过 `@role common` 生成默认常用集合，运行时由 `CommonV3` 把默认项与用户学习项合并。符号网格点击不激活主窗口，输入直接发送到仍有焦点的外部控件；剪贴板用消息重试。Emoji 保留内嵌压缩 PNG，只对可见内容异步解码，并通过 384 项 LRU 限制内存和 GDI 对象。

**Tech Stack:** C11、单个 C++ DirectWrite/WIC 桥接单元、Win32 API、CMake/MSVC、Python 3 构建与静态测试、PowerShell Win32 集成测试、Git/GitHub CLI。

### Task 6: 用单工作线程和 384 项 LRU 取代全量预热

- [ ] **Step 1: 写缓存失败测试**

构造 385 个不同键，验证容量始终不超过 384，最近访问项保留、最老项淘汰；重复请求只入队一次；取消后工作线程退出。静态测试禁止调用 `ys_warm_emoji_layout_cache` 和 `YS_EMOJI_WARMUP_MAX_THREADS`。

```powershell

```

Expected: FAIL，当前缓存上限为 4096 且仍全目录四线程预热。

- [ ] **Step 2: 拆分图片缓存和字体回退缓存**

图片缓存槽保存 36×36 HBITMAP、最近访问时钟和占用状态；字体回退缓存保留现有布局。图片查找命中时只在持锁期间增加引用/更新时间，绘制结束后释放临时引用，确保 LRU 不会删除正在绘制的位图。

- [ ] **Step 3: 实现单线程请求队列**

renderer 创建一个事件、一个互斥保护队列和一个工作线程。绘制 miss 时复制 UTF-16 文本到固定队列并去重；工作线程用私有 WIC 上下文解码，插入 LRU 后 `PostMessage` 主窗口的 Emoji-ready 消息。退出时先置 cancel、SetEvent、WaitForSingleObject，再释放资源。

- [ ] **Step 4: 接入可见区和下一屏预取**

绘制当前可见单元时自然提交高优先请求；类别切换和滚动完成后枚举下一屏符号提交低优先请求。队列满时丢弃低优先预取，不丢当前可见请求。

- [ ] **Step 5: 验证 GREEN 和资源上限**

```powershell

python tests\emoji_images_check.py
```
